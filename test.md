#### Why a Vertical Kitchen Garden?

We needed a demo that was technically complex yet universally understandable. A vertical kitchen garden is a tangible product that perfectly illustrates a classic documentation challenge: **sophisticated branching logic**.

The vast number of possible configurations makes it an ideal candidate for demonstrating how {{el.docsAssemblerExtension_link}} tames complexity through features like:

*   **Variables:** Manage product names ('SolisCell™'), shared text, and URLs in one place. Change a variable once, and it updates everywhere.
*   **Shared Steps:** Reuse common instructions (like 'Fauna Categories') across multiple configuration paths without duplication.
*   **Nested Maps:** Break down immense complexity into manageable, independent modules. Power options, crop choices, and frame assembly can each be self-contained maps.
*   **Extracted Logic:** Isolate a complex branch (e.g., an entire solar panel configuration) into a separate, reusable component, keeping the main guide clean.
*   **Step Variables:** Track user choices (e.g., `selected_module = "Solo"`) to deliver dynamic, personalized guidance and generate custom output.
*   **Auto-Adjusted URLs:** Ensure every link and image path remains valid, no matter how deeply nested or reused the content becomes.

In short, this demo isn't about gardens; it's a practical showcase of how {{el.docsAssemblerExtension_link}} masters the intricate decision-making inherent in every complex product, service, or operational procedure.
